# Candidate qualification

Qualification precedes selection. Every frozen candidate receives a typed receipt. Required failures block; optional failures remain in the immutable receipt set and do not prevent other candidates from being qualified. Only after the complete set satisfies the minimum root count may the selector be called, exactly once. Reruns are zero.

Qualification consumes provenance, licensing, release compatibility, and denylist state only. Parser accuracy, evaluator results, trust coverage, and semantic metrics are absent. The disclosed three candidates are intrinsically license/provenance verified for regression purposes but have future status `DENYLISTED`, so none is an eligible future root.
